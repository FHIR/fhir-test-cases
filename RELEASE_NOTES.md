* validator/manifest.json is restructured: the tests are now in suites (one for each former module, with a name and an optional description), and each suite has a sub-suite for each FHIR version it has tests for (version - 1.0, 1.4, 3.0, 4.0, 4.3, 5.0 or 6.0 - and its tests), so that a validator for one version can pick out its tests. Each test has a name (unique for its FHIR version) and a file. The test-cases object, and the module property of each test, are gone, so test runners need updating. validator/readme.md describes the new layout, the expected outcome files for each validator, and the tags, and refers to the manifest's own documentation for the test properties; it also says the java tests use tx-dev.fhir.org
* Add validator test vs-required-supplement (tx, R4): a v3 ActCode code bound to a Canadian value set that requires the Infoway fr-CA supplement to v3 ActCode. Neither is loaded locally: the validation has to go to the Canadian server, which the terminology ecosystem finds
